I.

The Gold Signal: Reward what matters, penalize what doesn't

The core insight

Most search analytics reward clicks. Problem: a click after a perfect match (query = product) is low-value — the user already knew what they wanted. The system learned nothing.

The highest-value signal is the inverse: clicked_despite_no_match. User searched for "iPhone 14 Pro case leather", we didn't have it, but they clicked on "iPhone 14 silicone case" anyway. This tells us:

  • They have genuine purchase intent (not browsing)
  • They're flexible on specification (leather → silicone)
  • We just learned a new product association

Gold Signal: clicked_despite_no_match = +15 reward points (highest weight in the system).

The reward formula

LDI uses a multi-signal reward calculator with anti-bait penalties:

class LDIRewardCalculator:
    weights = {
        'high_confidence_match': 10.0,
        'clicked_despite_no_match': 15.0,  # 🏆 GOLD SIGNAL
        'clicked_alternative': 20.0,
        'quick_click_bonus': 10.0,         # <10s to click
        'cart_add': 35.0,
        'purchase': 50.0,
    }
    
    penalties = {
        'bounce': -100.0,                  # Instant normalization to -1.0
        'multiple_refinements': -15.0,     # >=3 query changes = frustration
        'long_session_no_action': -10.0,   # >3min without click
    }

Key design: bounce detection is instant penalty. A user who leaves in <5s without any action is normalized to -1.0 regardless of other signals. This prevents clickbait patterns from polluting the training data.

II.

Semantic Validation: Filtering noise before it reaches the model

The problem with raw query logs

E-commerce search logs are 60-70% noise: keyboard mashing (asdfgh), incomplete prefixes (ip), food queries on an auto parts store (pizza), and hallucinated products (iPhone 30).

If you train on this data, you train on garbage. LDI implements a SemanticValidator that rejects low-quality queries before they enter the reward pipeline.

Validation layers

class SemanticValidator:
    def validate(self, query: str) -> Tuple[bool, str]:
        # 1. Keyboard patterns
        if re.match(r'^[asdfghjkl]+$', query):
            return False, "KEYBOARD_PATTERN"
        
        # 2. Unrealistic models (iPhone 30, Galaxy S99)
        for prefix, (min_num, max_num) in unrealistic_model_patterns.items():
            if model_num > max_num:
                return False, f"UNREALISTIC_MODEL:{prefix}_{model_num}"
        
        # 3. Food/wrong domain
        if has_food_words and not has_domain_context:
            return False, "FOOD_DOMAIN"
        
        # 4. NO_MATCH without domain context = noise
        if confidence_level == 'NO_MATCH' and not has_domain_context:
            return False, "NO_MATCH_NO_CONTEXT"
        
        return True, "OK"

The unrealistic_model_patterns dictionary knows that iPhone goes 1-16, Galaxy S goes 1-25, BMW series go 1-8. "iPhone 30" is rejected as hallucination, not counted as lost demand.

Why NO_MATCH with domain context is valid

If a user searches "BMW E46 klocki Brembo" and we get NO_MATCH, that's not noise — that's genuine lost demand. The query has domain context (car brand + part brand). These queries are flagged VALID_LOST_DEMAND and routed to the Gold Signal pipeline.

III.

Universal Automotive Knowledge: 300+ brands, zero hallucinations

The domain knowledge layer

LDI was built for automotive e-commerce. The UNIVERSAL_AUTOMOTIVE_KNOWLEDGE dictionary contains:

  • 300+ car brands — from BMW to BYD, including Chinese EV brands
  • 150+ motorcycle brands — Yamaha, Ducati, Royal Enfield
  • 500+ car models — E46, W124, A4 B8, etc.
  • 200+ part categories — klocki, amortyzator, filtr oleju
  • OEM suppliers — Bosch, Brembo, Mann, NGK

Why this matters

When a user types "Brembo klocki E46", the system knows:

  • Brembo = known OEM supplier (brake specialist)
  • klocki = brake pads (part category)
  • E46 = BMW 3-series 1998-2006 (car model)

This context enables fuzzy matching: even if we don't have "Brembo brake pads for E46" in the product database, we can suggest "ATE brake pads for E46" — and if the user clicks, that's a Gold Signal.

Latency budget

Classification happens while the user types. The <60ms p95 latency comes from:

  • Pre-loaded product database (in-memory)
  • Pre-compiled regex patterns for validation
  • FuzzyWuzzy process.extractBests() with score_cutoff
  • No external API calls in the hot path

VI.

Test results: 100 scenarios, 91% accuracy

Test methodology

The test suite covers edge cases that break naive matchers:

  • Typos in brand names (merecedes → Mercedes)
  • Polish diacritics (klocki hamulcowe vs klocki hamulcowe)
  • Mixed language queries (BMW oil filter 5W30)
  • Hallucinated products (iPhone 30, Galaxy S99)
  • Food domain leakage (pizza on auto parts store)
  • OEM code formats (1J0 615 301 = VW brake disc)

VII.

The gap in standard analytics

To understand why LDI matters, consider what standard tools see:

From an internal analysis comparing LDI methodology to enterprise analytics:

"Google Analytics 4 and internal logs only see Events (clicks, page views).
LDI sees Intents that never became events.

When a user enters a query and gets 0 results, standard systems treat this as a 'Bounce'. LDI does something different: in under 200ms, it runs a 5-stage analysis to determine whether this is noise — or genuine demand for a product the catalog doesn't carry."

The difference is brutal. A bounce is a dead metric. A classified intent is actionable data: inventory gaps, pricing signals, product associations, training labels.

Epilogue: Why this matters for e-commerce

Every e-commerce store has a "lost demand" problem. Users search for products that don't exist in the catalog. The search returns "no results" or irrelevant suggestions. The user leaves.

Standard analytics cannot capture this. They see a bounce. They don't see the intent.

LDI captures the intent. It logs what users wanted, not just what they bought. It identifies which "no results" queries are genuine demand signals (Gold Signal) vs. noise (keyboard mashing, wrong domain).

This data is the highest-value signal for inventory decisions and AI training. It tells you what to stock. It tells you what associations to learn. It's the signal that standard analytics miss.

We don't track what users bought. We track what they wanted.
